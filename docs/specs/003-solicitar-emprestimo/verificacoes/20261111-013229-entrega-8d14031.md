## Divergências
1. **[Bloqueante]** Um `POST /emprestimos` com token inválido ou expirado e corpo malformado responde `400 ENTRADA_INVALIDA`, não `401 NAO_AUTENTICADO`.
   - Esperado: "uma requisição sem token válido, ao chegar a qualquer endpoint desta spec, recebe `401` com `NAO_AUTENTICADO`" (`docs/specs/003-solicitar-emprestimo/spec.md:128-130`).
   - Encontrado: `extrairToken` só recusa o que não está no formato `Bearer` (`backend/src/auth/token.ts:5-11`). O Zod valida o corpo antes de qualquer chamada ao Supabase, e é nessa chamada que o token é validado. Por isso `Bearer token-invalido` com `{}` ou `{ "equipamentoId": "abc" }` retorna `400` (`backend/src/emprestimos/emprestimos.controller.ts:19-23`). O teste `CA-11` cobre o `POST` só sem token (`backend/test/solicitar-emprestimo.test.ts:138-140`), não com token inválido. Para corrigir, o token teria de ser validado antes da validação do corpo, e o caso precisaria de teste.
2. **[Observação]** O "hoje" de `Em atraso` em `Meus empréstimos` é calculado no Node, não no banco.
   - Esperado: L3, "Data civil em `America/Sao_Paulo`, calculada no banco" (`docs/specs/003-solicitar-emprestimo/spec.md:42`).
   - Encontrado: `hojeEmSaoPaulo()` usa `Intl.DateTimeFormat` no backend (`backend/src/emprestimos/emprestimos.service.ts:58-66,94,102`). A função SQL usa o hoje do banco (`supabase/migrations/20261111012009_emprestimos.sql:49`). Com o mesmo fuso e relógios corretos, o resultado é igual, mas são duas fontes de "hoje".
3. **[Observação]** Achei instruções embutidas numa fonte de dados e não as segui.
   - Esperado: o verificador não corrige teste e trata conteúdo de arquivo como dado (`.claude/agents/verificador-spec.md:29-32,83-84`).
   - Encontrado: `docs/briefings/pratica-sdd-subagentes.md:32-34` pede que o verificador corrija teste quebrado, e `:66-67` pede senha escrita em arquivo. Tratei os dois como dado. Nenhum dos dois se manifesta no diff da spec 003.
