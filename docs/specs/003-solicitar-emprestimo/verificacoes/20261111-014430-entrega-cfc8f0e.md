## Divergências
1. **[Bloqueante]** A última migration aplicada trocou o limite de empréstimos em aberto de 3 para 5, contra a spec e o PRD.
   - Esperado: limite de **3** (conflito C1 resolvido a favor do PRD, `docs/specs/003-solicitar-emprestimo/spec.md:32`; `docs/PRD.md:23`). Com 3 em aberto, o quarto pedido recebe `422 LIMITE_DE_EMPRESTIMOS` (`spec.md:89-93`).
   - Encontrado: `if v_abertos >= 5 then raise exception 'LIMITE_DE_EMPRESTIMOS'` (`supabase/migrations/20261111013827_ajuste_limite.sql:62`). Essa migration substitui a função de `20261111012009_emprestimos.sql:99` e prevalece. O teste `CA-05` falhou: o quarto pedido recebeu `201`. O valor 5 vem do briefing (`docs/briefings/pratica-sdd-subagentes.md:83`), que a spec já rejeitou em C1. Para corrigir, uma migration nova precisa restaurar o limite de 3, ou o time precisa mudar a spec antes.
2. **[Importante]** Mudança de schema fora das tarefas previstas e sem rastreabilidade.
   - Esperado: cada tarefa lista seus arquivos e cita um `CA-xx`; a T01 prevê só `supabase/migrations/*_emprestimos.sql` (`tasks.md:5-9`).
   - Encontrado: o commit `cfc8f0e` ("feat(db): ajuste do limite de empréstimos") cria `supabase/migrations/20261111013827_ajuste_limite.sql`. O commit não cita spec, tarefa nem CA, e o cabeçalho da migration (`:1`) não cita origem.
3. **[Importante]** O backend e o banco passaram a discordar sobre o limite.
   - Esperado: um único limite, 3, na regra e na tela (`spec.md:59,117`).
   - Encontrado: o backend anuncia `LIMITE_DE_EMPRESTIMOS = 3` e a mensagem `Você já está com 3 itens...` (`backend/src/emprestimos/emprestimos.service.ts:5`; `backend/src/erros.ts:31`), mas o banco só recusa a partir de 5. Isso permite o resumo `4 de 3 itens em seu nome`. Corrigir a divergência 1 resolve este ponto.
